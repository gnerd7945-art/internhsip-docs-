types of error:-
1) Connection timed out means:
The TCP connection attempt did not receive the expected response within the timeout period.
The client expects either:
SYN-ACK   → "Yes, TCP connection can be established"
or:
RST       → "I am reachable, but this port is refused"
 The cause could be:
AWS Security Group silently dropping the packet
AWS Network ACL dropping it
1) Linux firewall dropping it
2) Routing problem / blackhole
3) Server is down
4) NAT problem
5) Packet is going somewhere unexpected
6) Server receives it but the response cannot return
-> Check the intermediate path
  Use:
  traceroute 3.108.63.85

2) connection refused:-
The destination IP is reachable, but no TCP service is accepting connections on that port."

------------------------------------------------------------------------------------------------------------------------------------------------------------------------//HOW VIRTUAL FIREWALL WORK:-
1) The physical network card (NIC) receives the electrical signal and copies the data packet into the server's system RAM.Then the The NIC driver hands the packet to the Linux kernel network stack. The kernel creates a virtual bridge (usually named docker0), which acts like a virtual network switch inside RAM. 
2) docker uses host linux's kernel firewall called iptables or nftables.
3) The kernel has specific hooks (called Netfilter) that look at packets after they enter the network card but before they reach any application or Docker container.
4) When you start Docker, it automatically writes invisible rules into these kernel hooks.
5) As the packet moves through RAM toward the virtual bridge (docker0), the kernel evaluates Docker's rules. If a rule says "Block Port 8080 for Container A," the kernel deletes the packet from RAM right there.
